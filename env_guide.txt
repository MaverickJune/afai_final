Setting up the AFAI training environment on Bouchet
====================================================

For teammates in a different PI group. This takes about 1.5 hours, mostly waiting on jobs, and you
only do it once. Run everything from a normal SSH login to Bouchet. Nothing heavy runs on the login
node; each step submits a Slurm job.


Step 1: Find your scratch folder
--------------------------------

    ls -d ~/scratch_*/$USER

You should see something like /home/abc123/scratch_pi_xyz/abc123. That's where models, datasets and
checkpoints will go.

If nothing shows up, run `ls -d ~/scratch_*` and use the folder for your group plus your NetID.
If you have no scratch folder at all, ask YCRC (hpc@yale.edu).


Step 2: Tell the scripts where your scratch is (one time)
---------------------------------------------------------

Replace the path with yours from Step 1:

    echo 'export SCR=$HOME/scratch_pi_xyz/abc123' >> ~/.bashrc
    source ~/.bashrc
    echo $SCR

The last command should print your scratch path. Every job you submit from now on uses this path
automatically.


Step 3: Get the code
--------------------

    git clone https://github.com/MaverickJune/afai_final.git ~/afai_project
    cd ~/afai_project

Always `cd ~/afai_project` before running `sbatch`. The jobs look for files relative to that folder.


Step 4: Download the container and build the analysis environment
-----------------------------------------------------------------

These two jobs can run at the same time:

    sbatch jobs/pull_slime.sbatch
    sbatch jobs/build_afai_env.sbatch

Check on them with `squeue --me`. They're done when they disappear from the list, after about
50 minutes for the container and 15 for the environment. You'll end up with:

    ~/containers/slime_v0.4.0-cu129.sif   training and inference software (18 GB)
    ~/envs/afai_env                       Python for analysis (7 GB)

Your home quota is 125 GB, so this leaves plenty of room. Check each job's output with:

    tail logs/pull_slime_*.out
    tail logs/build_afai_env_*.out

The build_afai_env log should end with a list of package versions and an "end:" line.


Step 5: Check that everything works
-----------------------------------

Each job uses 1 GPU for a few minutes. Submit them one at a time, waiting for each to finish:

    sbatch jobs/verify_container.sbatch       # software versions + GPU
    sbatch jobs/verify_sglang.sbatch          # inference server
    sbatch jobs/verify_convert.sbatch         # checkpoint conversion
    sbatch jobs/verify_router_freeze.sbatch   # training with frozen router
    sbatch jobs/verify_afai_env.sbatch        # analysis env reads the checkpoints

What to look for in logs/:

    verify_container_*.out       "sm_90 in list: True | sm_100 in list: True", no errors
    verify_sglang_*.out          an answer containing 391 and a sentence about Paris
    verify_convert_*.out         "RESULT: PASS"
    verify_router_freeze_*.out   "ROUTER FREEZE TEST: frozen=PASS control=PASS"
    verify_afai_env_*.out        text generated by two models

If one fails, send the log file to the repo owner.


Step 6: Download the 30B model (only needed for training)
---------------------------------------------------------

You can't read another group's scratch, so you need your own copy (about 25 minutes, 115 GB of
scratch):

    D=$(sbatch --parsable jobs/download_30b.sbatch)
    sbatch --dependency=afterok:$D jobs/convert_30b.sbatch

The second job starts automatically when the first succeeds. logs/convert_30b_*.out should end with
"RESULT: PASS".

WARNING: scratch deletes files older than 30 days. If the model disappears, just re-run Step 6.


Step 7 (only if you use Claude Code)
------------------------------------

Open ~/afai_project/CLAUDE.md and replace the scratch_pi_lz484/wb379 paths with your scratch path
from Step 1. Your Claude Code will then follow your storage layout.


Getting updates
---------------

    cd ~/afai_project && git pull


Good to know
------------

- Read SETUP.md in the repo for how to run training and analysis jobs.
- Never write `conda create -n ...`; the env setup above avoids a quota problem.
- Real 30B training uses a full 8-GPU node (gpu_h200 or gpu_b200 partition). If your account can't
  use those partitions, ask your PI or YCRC. Steps 1-6 only use the day and gpu_devel partitions.
- Wait until the repo owner confirms the 30B test run worked before starting real 30B runs.
